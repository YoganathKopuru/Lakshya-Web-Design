# Website QA and engineering review — 30 October 2026

Baseline: GitHub commit 4b312226a6adc6b5a17fae737747a16928e630d7.

## Executive assessment

The static build and internal navigation checks pass. The website is a functional preview, but this review does not certify public-launch readiness. Contact conversion, accessibility, search metadata and ongoing content ownership need work. No code was changed during this audit.

## Coverage and evidence

- A fresh production build passed compilation, TypeScript validation and static export (18 framework-generated pages).
- Parsed all 17 exported HTML files, including both 404 representations: homepage; Work; Industries; Company; Careers; Contact; services index; all eight expertise details; 404.
- Checked 361 internal link/anchor occurrences against exported files and IDs: zero missing destinations.
- Every exported HTML file has one H1 and one main landmark. No duplicate IDs or images missing an alt attribute were found. This does not establish alt-text quality or complete accessibility compliance.
- Reviewed shared navigation, enquiry form, service walkthrough state/timers, AI orbit control, page metadata, responsive CSS and content boundaries.
- Earlier implementation browser checks in this chat verified Play/Pause/Reset on Software Engineering, orbit pause, the software enquiry preselection, and the homepage review grid at a 390px viewport. Those checks were not repeated in this audit.
- NOT verified in this pass: a fresh browser interaction matrix across every route; Safari/Firefox; real iOS/Android; 200–400% zoom; screen-reader output; measured contrast throughout; external link availability; email-client delivery; live HTTP/security headers; Lighthouse/Core Web Vitals; dependency vulnerability advisories. These remain explicit coverage gaps, not passes.

## Findings and recommendations

### P1 — Prepared email draft becomes stale (confirmed source defect)

Location: `src/components/enquiry-form.tsx`, `submit` and `draft` state.

Reproduce: complete the form, prepare an enquiry, change name/message/service, then use the existing Open email draft link without preparing again. The URL is only regenerated on submit, so the previously entered values are sent to the email app.

Fix: invalidate the prepared draft on every relevant form change, or derive it from the current validated values when the visitor opens it. Add a regression test covering changed message and service.

### P2 — Required text fields accept whitespace (confirmed source defect)

Name/company rely on browser `required`; message relies on `minLength=10`. Neither trims content. A name or company containing spaces and a message containing ten spaces can satisfy these constraints.

Fix: normalize and validate trimmed values with clear field errors. Preserve the user's meaningful formatting in the final message.

### P2 — Menu dismissal does not restore focus (source-confirmed accessibility gap)

Location: `src/components/chrome.tsx`. Escape removes the expertise menu but does not return focus to its disclosure button. When focus was inside the removed menu, keyboard context can be lost. Active navigation also uses only a visual class, without `aria-current`.

Fix: retain trigger refs, restore focus on keyboard dismissal, and mark the current page. Verify forward/backward tab order and mobile menu behavior in a browser. Do not assume a disclosure menu needs a modal focus trap; select semantics deliberately.

### P2 — Small secondary copy and low-contrast candidates (review concern)

Global styles and review cards contain 7–10px labels, notes and links, including meaningful source dates. Several use muted green/gray on pale surfaces. Exact rendered contrast has not been measured.

Fix: raise meaningful secondary copy toward 12–14px, measure actual color pairs, and check zoom and touch targets at 320/390/768/1024/1440px. Treat contrast violations as unconfirmed until measured.

### P2 — Email-only enquiry flow limits conversion (product limitation)

The interface accurately says it prepares an email; there is no server submission or receipt. Users without a configured email handler must manually compose a message. A 4,000-character message can produce a long encoded mailto URL whose compatibility varies by client.

Improvement: provide Copy enquiry text as a near-term fallback. For public launch, consider a server endpoint with server-side validation, rate limiting, spam protection, delivery retries and an honest success state. Never expose mail-provider secrets in the frontend.

### P2 — Search/social metadata is incomplete (source gap)

Root metadata defines title and description, but no canonical URL, Open Graph image or social card. The source tree has no sitemap or robots route.

Improvement: once the final public domain and indexing decision are agreed, add canonical URLs, route-specific descriptions, sitemap, robots policy and social previews. Avoid indexing a private preview by accident. Add Organization structured data only for verified facts.

### P2 — Public-launch content still needs approval (known boundary)

Careers explicitly says openings are not displayed on this preview. Work items are delivery areas rather than approved case studies. Glassdoor is a dated public-index snapshot, not a live feed. Legal/privacy content is absent from the footer.

Improvement: assign owners for capability copy, hiring content, approved case studies and review refreshes. Decide privacy/legal requirements against actual data collection before adding a server form or analytics. Do not fabricate client proof or vacancies.

### P3 — Walkthrough pace and status need usability review

The service flow advances every 1.6 seconds and announces each selected description through a polite live region. This may be too fast for reading or assistive technology. Offscreen playback stops its timer but leaves `playing` true, so it resumes on return and can display a pause label while not advancing.

Improvement: trial a slower interval, provide a clear paused/offscreen state, and test screen-reader announcements. Preserve manual stage selection and reset.

### P3 — Maintainability and development workflow

Several TSX files and much of globals.css are compressed into very long lines. The shared Header/Footer module is a client component and includes static footer content. `package.json` has a `start` command using `next start`, although the app uses static export.

Improvement: format the source consistently, split static server-rendered chrome from interactive navigation, remove obsolete global styles after usage review, pin package-manager/runtime versions, and document a supported static-preview command. Add CI for frozen-lockfile installation, type checking, production export and internal-link checks. Add focused interaction tests for form edits, navigation dismissal and walkthrough state, rather than snapshotting every decorative diagram.

## Recommended next sequence

1. Fix stale drafts and whitespace validation; verify keyboard menu dismissal.
2. Run the missing browser/device/accessibility matrix and record screenshots, console errors and measured contrast results.
3. Improve secondary text readability and email fallback based on those results.
4. Finalize public-domain metadata and content ownership; choose the backend form/ATS scope.
5. Establish CI and monitor real performance after public deployment. Current build reports about 117 kB first-load JS on the homepage and 118 kB on service pages; these are build estimates, not measured user performance.

No security penetration test, legal certification, or complete accessibility certification is implied by this report.
